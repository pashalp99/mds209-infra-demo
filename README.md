# MDS209 infra demo: an industry data stack, laptop-sized

A runnable demo for the Week 9 guest lecture, *Data systems that survive reality*.

It turns monthly exports from a restaurant group into two decisions, **how much duck to order** and
**how many staff to roster**, through the same five layers as a production lakehouse on Google Cloud.
Here they run on a laptop in about 10 seconds, with one dependency (DuckDB).

All data is synthetic. *Warung Bebek Nusantara* is a fictional brand; every order, name and phone
number is generated by `pipeline/capture.py`.

## Quick start

Needs Python 3.10+ and `make` (macOS and Linux have both).

```bash
make all                 # creates .venv, simulates the exports, runs every layer
open reports/report.html # macOS; on Linux use xdg-open
```

Then break it on purpose:

```bash
make break SCENARIO=rename      # GrabFood renames a dish         → a check stops the run
make break SCENARIO=timezone    # GoFood silently switches to UTC → a check stops the run
make break SCENARIO=duplicate   # POS re-sends a month            → handled, but flagged
make break SCENARIO=overwrite   # someone edits a landed file     → land refuses
```

`make help` lists every target. `make reset` deletes all generated data.

## The five layers

| Layer | Here | In the airline stack |
|---|---|---|
| 01 Capture | `pipeline/capture.py` drops monthly exports into `data/landing/` | Datastream change capture from SQL Server |
| 02 Land | `pipeline/land.py` copies them to `data/raw/`, read-only, with a SHA-256 manifest | Raw zone on Cloud Storage |
| 03 Store | `pipeline/store.py` writes Parquet + lineage columns to `data/lake/bronze/` | Apache Iceberg tables |
| 04 Transform | `sql/models/*.sql`, run in order by DuckDB | Spark on Dataproc + Dataform |
| Checks | `sql/checks/*.sql`: each query returns the rows that break a rule | Dataform assertions |
| 05 Serve | `sql/serve/*.sql` + `pipeline/serve.py` → `reports/` | BigQuery + dashboards |
| Schedule | `Makefile` | Cloud Composer (Airflow) |

More detail, and when each layer is worth upgrading: [docs/architecture.md](docs/architecture.md).

## What each lecture story looks like in code

| Story | Where to look |
|---|---|
| 1 · Sold out is not low demand | `stock` exports carry `sold_out_at`; `mart_demand_hourly.is_censored`; `sql/serve/10_forecast.sql` estimates demand after a sell-out; report section 3 scores both forecasts |
| 2 · Five systems, five names for one dish | `seeds/menu_alias.csv`, `seeds/outlets.csv` (GoFood and GrabFood name outlets their own way), `seeds/recipe.csv` (portions → whole birds) |
| 3 · Keep the history | `data/raw/` is never edited; `dim_menu_history` keeps every price and the July menu change; TGR-01 opened in August |
| 4 · One forecast, two decisions | `sql/serve/30_stock_plan.sql` (ingredient × outlet × day) and `40_staff_plan.sql` (outlet × shift, busiest hour) |
| Privacy | `customer_phone` and `staff_name` never leave raw; check 07 fails if they reach a clean or mart table |
| Calendar | `seeds/calendar_events.csv`: Ramadan, mudik, Lebaran closures |
| Reproducible from a clean clone | `make all`; settings in `config/pipeline.json`; `data/` is in `.gitignore` |

## Project layout

```
config/pipeline.json   dates, paths and forecast settings
seeds/                 reference data the team maintains (versioned in Git)
pipeline/              one Python module per layer, plus checks and break_it
sql/models/            staging → clean → mart
sql/checks/            data quality rules (error / warn / info)
sql/serve/             forecast, backtest, stock plan, staff plan
docs/                  architecture notes and the live demo script
data/   (generated)    landing, raw, lake, warehouse.duckdb, _truth
reports/ (generated)   report.html, data_quality.json, plan CSVs
```

## A note on `data/_truth/`

Because this is a simulation, the generator also records **true demand**, including what customers
wanted after the duck sold out. It is used only to score the backtest. A real project never has it,
which is exactly why the sold-out time has to be captured.
